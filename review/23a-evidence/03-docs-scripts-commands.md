## 5. `CF-DOC-001` verification

- Source implementation: `tailtriage-analyzer/src/ratio.rs` defines `pub(super) fn meets_ratio(higher: u64, lower: u64, numerator: u64, denominator: u64) -> bool`.
- Exact expression: `lower > 0 && u128::from(higher) * u128::from(denominator) >= u128::from(lower) * u128::from(numerator)`.
- Implementation comments say analyzer option validation owns nonzero ratio components, while this helper owns inclusive boundary, zero-baseline rejection, and exact cross-multiplication for scoped movement policies.
- Unit tests in the same file verify inclusive boundary behavior, zero-baseline rejection, large qualifying/non-qualifying values, and exact behavior near `u64::MAX`.
- Current prose requiring carry-forward: `docs/analyzer-rationale.md` contains the sentence `This structural change does not alter reports or option paths.` in the analyzer rationale material for scoped ratio comparison.
- Other prose/search findings: repository prose discusses parity extensively for tracing/demo/report contracts and mentions saturation in collector-limit contexts and changelog collector optimization, but no other prose was found that states the precise `u64` saturated-cross-product to exact-`u128` scoped-ratio behavior distinction.
- Mechanically supported behavior difference: scoped ratio comparisons are now exact `u128` cross-products rather than any saturated `u64` cross-product behavior. For ordinary fixture-scale values and option paths, output parity can remain true. For extreme valid `u64` values, previous saturated cross-products could collapse distinct products at `u64::MAX`; the exact `u128` comparison can therefore produce different, corrected movement results and reduce false-positive movement detection.
- What remains preserved: public option paths, nonzero option validation ownership, inclusive threshold semantics, zero-baseline rejection, and ordinary fixture/report output where values do not overflow `u64` cross-products.
- What intentionally changed: arithmetic exactness for valid high-magnitude values near `u64::MAX`, including cases where `higher * denominator` and `lower * numerator` would previously saturate and compare equal.
- Validation surfaces relevant to a later correction: `tailtriage-analyzer/src/ratio.rs` unit tests, analyzer fixture tests, `scripts/diagnostic_benchmark.py` deterministic corpus, `docs/analyzer-rationale.md` rationale contract, and docs contract tests.
- CF-DOC-001 result: verified. The broad parity sentence is inaccurate for extreme valid values, while ordinary option paths and fixture-scale outputs remain preserved.
